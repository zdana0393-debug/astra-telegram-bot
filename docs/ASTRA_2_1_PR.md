# Astra 2.1: атомарный учёт пыли и восстановление оплаченных раскладов

В 2.0 сбой между реферальным флагом и начислением теряет награду, а платный расклад не сохраняется до отправки. Кандидат 2.1 проводит операции, баланс и ledger атомарно через SQLite triggers и хранит оплаченный текст для восстановления без второго списания. Привязка сообщения-меню к заказу предотвращает повторную покупку при callback/webhook retries, включая сбой после выдачи восстановленного заказа.

Добавлены повторяемая additive миграция с opening-балансами, leases webhook/delivery, каскад удаления и очистка ссылок, защищённая диагностика, single-file Worker и write-free maintenance для безопасной паузы. Цены, бонусы, меню, бесплатный прогноз с числом дня и контент карт сохранены. Исходный src/ не изменён.

Проверено на Node.js 24.22.1 командой `sh scripts/test.sh`: исходные 30 assertions (48 fake calls), адаптированные 30 assertions (45 fake calls), 28 новых тестов, все passed, 0 failed/skipped. Проверены параллельные списания через 8 SQLite-соединений, ABORT/rollback, повтор миграции, ошибки Telegram 400/403/429/500/сети/JSON, удаление, Cron, переход московской даты. `git diff --check` и syntax checks проходят. Telegram полностью замокирован.

Обязательные пункты ревью: D1 staging ещё не выполнен; нужны проверенный backup, пауза всех writers, миграция и SQL-контроль. Оригинальный v2 нельзя запускать поверх новых triggers: безопасный откат — maintenance и forward fix. GET /activate намеренно отключён, существующий webhook не меняется. Неопределённая доставка может дать повтор того же оплаченного текста без второй оплаты; Cron консервативно допускает пропуски вместо автоматических дублей.

Подробности: ASTRA_2_1_AUDIT.md, ASTRA_2_1_MIGRATION.md, ASTRA_2_1_DEPLOY_FOR_BEGINNER.md, ASTRA_2_1_RELEASE_NOTES.md и ASTRA_CURRENT_STATE.md. Не выполнять deploy/remote SQL/изменения webhook по этому PR. Не сливать автоматически. Production и секреты не затронуты.
