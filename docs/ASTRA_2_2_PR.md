# Astra 2.2: навигация и художественная оболочка для staging

Base: astra-2.1-hardening. Шесть разделов и вложенная справка дают доступ ко всем функциям 2.1; добавлены манифест, честная методология, команда-легенда, 11 коротких/подробных FAQ, фактическое досье и заглушки будущих сервисов. Single-file release/ASTRA_2_2_WORKER.js построен на сохранённом 2.1, без npm/платных API.

Пасхалка GPT6 начисляет +5 один раз на профиль через новую таблицу и атомарный trigger с ledger reason=easter:gpt6 и operation_id=NULL. Исходные CHECK/операции не меняются. Удаление работает с FK OFF, частичная/отсутствующая миграция даёт 503. Для Console есть четыре отдельных SQL-шагa. BOT_USERNAME — безопасная переменная тестового бота. Новый путь Таро подтверждает цену и сохраняет один ключ покупки при повторах; старые callbacks совместимы.

Проверка: sh scripts/test-2.2.sh, Node 24.22.1. Исходные 30 assertions; регрессия 30 и hardening 28 на 2.1; те же 30+28 на 2.2; 20 новых node:test, все прошли, 0 failed/skipped. Проверены 10 параллельных наград, ledger rollback, FK ON/OFF, повтор миграции, навигация и лимиты текста, отказ/повтор Telegram, цена −3, бонусы, число дня и совместимость отката на 2.1. Секреты и внешние сервисы не использованы.

Только для тестового Worker astra-staging-21-worker и D1 astra-staging-21. Требуются ручные backup/миграция/проверка D1/телефона по docs/ASTRA_2_2_STAGING_GUIDE.md. SQLite не доказывает distributed D1 или лимиты Free; exactly-once доставки Telegram не обещаем. Готовность локального кандидата не означает деплой. Не менять production, webhook/Cron settings, не сливать main автоматически.
