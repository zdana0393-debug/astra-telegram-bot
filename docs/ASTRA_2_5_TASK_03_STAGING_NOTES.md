## Техническая запись ограничения чтения

Для повторного чтения используется одна запись существующей `astra_update_jobs` на живой профиль: `update_id=-telegram_id`, status=done, lease=`t25r|generation|state|nonce`. Telegram update_id в кандидате проверяется как неотрицательный, поэтому пространства не пересекаются. Это блокировка/5-секундный cooldown чтения, а не операция кошелька и не бессрочная база удалённых ID. Lease отправки30сек, исходная доставка TASK02 —60сек. Профильная SQL-проверка действует перед каждой частью. `astra_erase` удаляет запись вместе с профилем даже при FK OFF; прежняя ограниченная очистка done-jobs старше14дней тоже применима. После ротации webhook-secret кнопки нужно открыть заново; ранее купленное остаётся в базе.

История показывает5 записей, курсор — короткий handle с MAC текущего владельца/поколения/сообщения/ключа. После VACUUM устаревший handle может перестать работать; он не открывает другую покупку благодаря подписи полного ключа. Нужно заново открыть историю. Длинный архив читается до3 частей за действие, затем явное продолжение после5сек; текст соединяется без изменений.
