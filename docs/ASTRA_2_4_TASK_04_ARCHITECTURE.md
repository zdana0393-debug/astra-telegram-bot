# TASK 04 — границы интерфейсного слоя

Основа 3fd93db включает принятый TASK 03 (389350b) и уточнения владельца к TASK 05. Последние сохраняются побайтно; TASK 05 не исполняется. Рабочая ветка astra-2.4-prestaging-ux-patch, fetch/pull выполнены с явной веткой: origin по умолчанию получает лишь main.

Новый src/ui04 содержит тексты/показ реального состояния и экранные адаптеры. scripts/patch-task04.mjs применяется последним к сборке; старые исходники, каталог гороскопов, тарифы/SQL 0021–0027, HMAC, платежные сервисы и broadcast остаются неизменными. Защищённый manifest и обратимость build patch показывают точные границы изменений.

Контроллеры списания/начисления остаются прежними. В их сообщениях изменяются только литералы и форматирование; недостаток пыли получает отдельный read-only экран с реальным балансом, текущими доступными способами накопления и магазином только при успешном paymentEnvironment. Старое предложение Таро за 3 не получает права списать 5; новый подтверждающий offer остаётся прежним. Paid/free тела не редактируются даже при повторном чтении. После Таро добавляется лишь кнопка существующего бесплатного прогноза, без нового сообщения/покупки.

Номинальные ставки выбираются по фактически активированной политике; пауза/неготовность защиты явно запрещает обещание начисления. До перехода показываются только прежние 2/+1/+5; после — 5/2/3/4/6, реферал 10/+3, канал15/+5. Финансовые flags и дата compact не задаются, Stars по умолчанию OFF. Поддержка/Terms/retention берутся только из принятой конфигурации; отсутствующие не выдумываются. Обмен назад не предлагается, обязательные споры/возвраты и их обслуживание сохраняются.

Для уведомлений новые пользователи по-прежнему OFF. Старый ON называется настройкой профиля, а не доказательством согласия. На существующем экране предлагаются явные «Подтвердить подписку»/«Отключить», на OFF — «Включить». Целевая запись использует прежнее поле notification_target в update_jobs, обеспечивая идемпотентность повторного update. Массовых изменений нет. Отдельного долговечного реестра версии согласия не создаётся; если владелец потребует отсечение старых ON в Cron, это отдельное согласованное решение и схема, не скрытое изменение TASK 03.
