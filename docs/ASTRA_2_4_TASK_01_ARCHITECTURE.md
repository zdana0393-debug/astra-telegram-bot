## Минимальный fence

Секрет ASTRA_BONUS_FENCE_KEY, отдельный key ID; HMAC-SHA256 с доменами owner и invitee. Fence содержит только key_id,псевдоним,purpose,reference,awarded_at,expires_at. Никаких исходных ID/имён/вопросов/текстов в fence. Профильные HMAC-aliases и исходная реферальная связь — обычные данные, удаляемые с профилем, включая FK OFF.

Initial/GPT6/channel/первый milestone и ежедневные права защищаются owner-псевдонимом. Invitee welcome, inviter referral и inviter channel — глобальным invitee-псевдонимом, чтобы смена inviter не обходила окно. Можно приглашать разных людей; глобальный запрет не относится ко всем приглашениям одного inviter. Сама связь/поколение inviter проверяются отдельно. Ежедневное право тоже переживает удаление, иначе повторная дата оставалась бы источником бесконечного+2.

Каждая успешная выплата создаёт fence и ledger в одном SQL statement с триггерами. Время — фактическое начисление, expiry=awarded_at+2592000секунд; попытки/повторы не продлевают окно. Однократность в живом профиле сохраняется и после TTL. Права старой версии импортируются только из наблюдаемой фактической операции/registration/GPT6/канала с достоверным временем, не из opening и не из предполагаемых посещений.

Удаление до переноса наблюдаемых старых прав при утраченном ключе не должно оставлять raw ID. Вместо тайного хранения вводится общий срок безопасной паузы бонусов до истечения30дней возможных старых прав; это неперсональный стоп-флаг. Требуется закончить перенос перед снятием maintenance. Обычное удаление не блокируется.

Для ротации активный key ID/контрольный HMAC закреплены в D1. Старые ключи, имеющие живые права, должны оставаться в отдельном previous-key ring до их expiry; новый профиль сопоставляется со всеми активными версиями. Неизвестный/изменённый ключ или потеря необходимого previous key блокирует выплаты и объясняется безопасным blocker в /health. ADMIN-header защищает конфигурацию/подтверждение уведомления; значения ключей не принимаются в JSON и не выводятся.

Срок права строго30дней. Просроченные записи очищаются ограниченными задачами; реальный физический срок удаления зависит от запуска очистителя и требует staging-проверки/мониторинга. Нельзя обещать D1-native TTL, которого здесь нет. Backup с истёкшими правами перед возобновлением writers очищается по реальному времени. Это персональные псевдонимизированные данные, не анонимизация; правовое основание/notice требуют решения владельца до публичной активации. Мультиаккаунтность не устраняется.
