# TASK 03 — очередь утреннего бесплатного прогноза

9 ноября 2026. Основа de954e2, только astra-2.4-prestaging-ux-patch. Новый формат 02B не включается автоматически; кэш и движок не редактируются. Никаких remote действий.

Исходный broadcast исключает любое существующее id/day, поэтому 429 не возобновляется. Восьмёрка — размер одного запуска, не всей аудитории; повторные вызовы могут выбирать следующую восьмёрку. Очистка старого кода срабатывает только ровно в 06:00 UTC. Фактическая причина недоставки без Dashboard неизвестна.

Добавляется отдельная НЕфинансовая 0027: outbox с попытками/сроком повтора/поколением профиля и глобальная неперсональная запись lease/cooldown. 0021–0026 побайтно сохраняются. Старый astra_broadcast_jobs остаётся журналом совместимости: прежние sending/unknown/rejected/sent не переотправляются. Новый claim и legacy marker создаются одним SQL statement с триггерами. Завершение/403 атомарно обновляют журнал и last_broadcast_day/opt-out. Явная очистка работает с FK ON/OFF и удаляет обычные очереди при /delete; бонусные HMAC-права не затрагиваются.

Максимум восемь кандидатов за invocation. Сначала свежие, затем созревшие 429-retry; максимум три попытки на профиль/день. Успешные/неопределённые/терминальные исключаются, так что список сам служит долговечным курсором без потери более низких новых ID. Общий lease защищает параллельные triggers; cooldown сохраняет retry_after даже при удалении профиля, не сохраняя его ID. 429 до любого принятого chunk допускает повтор; после частичной отправки — unknown без автоматического дубля. Сеть/timeout/5xx/повреждённый ответ/сбой записи после принятого сообщения также unknown. Exactly-once с Telegram не обещается.

Cache сначала читается в выборе кандидатов; отсутствующий создаётся прежним getForecastDaily. Claim выполняется ПОСЛЕ подготовки текста, непосредственно перед HTTP, и заново проверяет opt-in, знак, поколение, дату, lease и cooldown. Между claim и первым send нет другого await. Между chunks выполняется дополнительная проверка. Уже начатый HTTP нельзя отозвать после /stop; это явно раскрывается. Дневная дата — фактическая Europe/Moscow, не старый scheduledTime. Окно 06:00–07:59 UTC сохраняется. Просроченный контент не досылается ночью.

Бесплатный текст тот же, что в меню; единственный платный CTA датирован и сначала открывает подтверждение 4. Уже купленный CTA ведёт только к repeat старой даты, никогда к списанию. Кнопки прикладываются к последнему chunk; обычные новые прогнозы — один пост. Начислений или activity hooks в Cron нет.

Существующие notifications flags сохраняются, нули не включаются. Новые регистрации получают OFF в JS INSERT, явный прежний toggle включает их. Старый DEFAULT 1 сам по себе не доказывает согласие; перед будущей установкой владелец проверяет основания старых флагов. Их массовое изменение или фиктивное повторное согласие в миграцию не встраивается.

Предварительный бюджет: отдельная проверка схемы/lease/ограниченная уборка и до восьми cold получателей; свежая проверка paid включена в RETURNING claim, finalize — один statement с триггерами. Измеряются D1 calls, statements и HTTP вместе; жёсткий invocation guard не допускает превышения даже при длинном старом кэше/ошибках. Локальные цифры не доказывают CPU 10 ms и rows_* на D1.

Прежние 629 тестов сохраняют исторический контракт версии до TASK 03; отдельный build switch нужен именно для этих ожиданий Cron/CTA. Затем итоговый Worker проверяется с 0027: 8/20/100, races, fault injection, 403/429/unknown, opt-in/out, день/окно, cache/owned CTA, отсутствие бонусов и бюджеты. Защищённые исходники/финансовые SQL проверяются по SHA. После отчёта commit и обычный push, без PR и TASK 04.
