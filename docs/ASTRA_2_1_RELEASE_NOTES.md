# Astra 2.1 — локальный кандидат для ревью

Не опубликован и не готов для production без staging. Рабочая Astra 2.0 не менялась.

## Изменения

- Single-file Worker в release/ASTRA_2_1_WORKER.js; npm/сборка/платный runtime не требуются. Исходные src/ — неизменённый snapshot для сравнения.
- Повторяемая additive миграция и операции с ledger: регистрация +2, день +1, реферал +5, канал +5, расклад −3. Сохранение баланса существующих пользователей через opening, без повторных подарков.
- Сохранённый текст оплаченного расклада, состояния pending/sending/sent/retry/unknown/rejected, lease отправки; после ошибки нет возврата с потерей результата, повтор пытается выдать тот же сохранённый текст бесплатно.
- Привязка меню к выбранной операции хранится в astra_tarot_requests до удаления профиля: retry после восстановления старого заказа не создаёт новую покупку.
- Повторные callback одного сообщения-меню — одна покупка. Для новой покупки открыть «Таро» заново. Старые сообщения Telegram имеют message_id и также защищены; fallback callback id используется только для неполных тестовых событий. Это осознанное изменение защиты от повторного списания, подписи кнопок прежние.
- Webhook jobs с working/done и арендами; target переключения рассылки сохраняется для безопасного retry. Срок дедупликации завершённых updates — 14 дней при работающем Cron.
- /delete очищает свои operations/ledger/jobs и чужие ссылки на ID; /privacy описывает реальные данные. Бонус повторной регистрации после удаления остаётся прежним.
- Рассылка хранит attempted/sent/unknown/rejected отдельно от last_broadcast_day. Неопределённые/отклонённые попытки не повторяются автоматически в тот же день; возможны пропуски. Прежнее окно/лимит 8 остаются.
- /health проверяет наличие схемы; unmigrated webhook/Cron не пишут. POST /internal/integrity под admin заголовком возвращает только агрегат расхождений balance/ledger; расширенная ручная диагностика в scripts/check_integrity.sql.
- GET /activate всегда 410; setWebhook удалён из кандидата. Рабочий webhook не нужно переактивировать. Будущие отдельные изменения webhook должны исключать секреты из URL и сброс очереди.
- В логах кандидата фиксированные сообщения без URL токенов, ID или исходного текста исключения. parse_mode не добавлен.

Функции прогноза, тексты фраз, 22 аркана, число дня, бесплатная карта, регистрация и основное меню сохранены. Astra 3.0/Stars/новые цены не реализованы.

## Проверки

Node.js 24.22.1, `sh scripts/test.sh`:

- исходная 2.0: 30 assertions, 48 fake Telegram calls;
- кандидат: 30 assertions, 45 fake Telegram calls. Три проверки активации адаптированы к намеренному запрету /activate вместо реального setWebhook; остальные исходные проверки сохранены;
- hardening: 28 node:test tests, 28 passed, 0 failed/skipped, включая 8 отдельных SQLite-соединений, откат при ABORT, миграцию, сбои доставки, каскад, Cron, контент и московскую полночь.

Все сетевые вызовы приложения в тестах замокированы. Локальная проверка single-file и syntax не заменяет staging D1. Никаких deploy, remote SQL, live Telegram, покупок, настройки webhook или чтения секретов не было.

## Ограничения и внедрение

Exactly-once внешней доставки не обещаем. После неизвестного исхода повтор оплаченного текста может продублировать сообщение без новой оплаты. Пропуск уведомления/рассылки возможен. Долгая приостановка процесса сверх аренды может вызвать дубли отправок. Нет автоматической очереди повторов/recovery Cron для платных результатов: восстановление по следующему нажатию/повтору webhook.

Миграция требует паузы всех writers, backup и staging. Оригинальный 2.0 несовместим с новым учётом как writer: нельзя откатывать его поверх новых triggers. Оперативный откат — write-free release/ASTRA_2_1_MAINTENANCE.js, затем forward fix, без удаления данных. См. отдельные документы миграции, аудита и внедрения.
