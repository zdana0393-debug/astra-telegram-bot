# TASK 02 — редакционный слой без замены выбора трактовок

9 ноября 2026. Основа — опубликованный TASK 01, 10c087a. Только ветка astra-2.4-prestaging-ux-patch. Экономика, SQL, HMAC, Stars, Cron и интерфейс платежей не изменяются.

Исходные engine.mjs, catalog.v1.json, configured.mjs и service.mjs остаются побайтно прежними. Новый компактный генератор получает результат прежнего генератора и его trace: ту же тему восьмидневной ротации, 6 unit, 6 sign lens, 2 modality lens, timing/contact, rune/symbol/advice и число. Повторной случайной выборки и смены seed нет. Новая engine_version обозначает композицию прежнего selection engine и нового presentation, а не используется как новый seed.

Отдельный редакционный справочник связывает каждую короткую смысловую запись с конкретным исходным ID, его semantic_key, директивами и контрольной суммой исходного содержания. Контекст стихии остаётся в тематическом тезисе; профильный акцент — в выбранном sign lens. Шестнадцать редакторских слияний сводят конкретные выбранные пары к одному тезису вместо двух смысловых повторов; обе исходные ссылки и контрольные суммы сохраняются. Это не новые случайные варианты или смена selection. Модальность может дополнить строку либо ограничить уже выраженный тезис: в trace явно указано, что показано и что оставлено проверяемым ограничением, без обязательного третьего предложения. Практические действия происходят только из отредактированных выбранных источников. Редакторские ограничения не выдаются за астрономию. Автоматические проверки доказывают происхождение и совместимость тегов, но не заменяют смысловое чтение человеком.

Бесплатный документ: шесть коротких разделов и бесплатное число с кратким значением. Один formatFreeForecast сериализует смысловой документ; ручное чтение получает его через сохранённый free_text. Существующий Cron уже обращается к той же функции кэша — его код не редактируется в TASK 02. Расширенный документ: новая развилка и способ применения из выбранной темы, конкретизация через исходный профиль, неизменные соответствия выбранных символа/цвета/руны и углубление числа, выбранный Совет Жирного.

Интеграция только в окончательный Worker 2.4 (маркер ASTRA-2.4-task02), отдельным build patch после TASK 01. Сборки прежних релизов остаются неизменными. getForecastDaily сначала читает существующую запись и никогда её не обновляет. Лишь на cache miss генератор учитывает необязательную ASTRA_FORECAST_COMPACT_START_DAY: без неё остаётся прежняя редакция, с ней новые даты от согласованной границы получают новую версию. Некорректная заданная дата запрещает создание нового текста, без красивого fallback; уже сохранённые строки остаются приоритетными. Дату реального включения выбирает владелец в будущем; код её автоматически не назначает. Покупка по-прежнему атомарно сохраняет snapshot за 4, повтор — по прежнему result_text.

Проверки: минимум 12×90, отдельные двенадцать дат повторяемости, полный selection parity, проверка всех опубликованных источников, мутации директив/ссылок/содержания, смысловые теги и повторы, UTF-16 Telegram limits; SQL cache/paid byte preservation и конкурентное создание; 12 знаков на дату, четыре последовательных дня, Дева 2026-11-08 до/после и несколько extended с источниками. Прежняя полная регрессия TASK 01 запускается без новой даты включения, новые тесты — с ней. Реальные D1/Telegram не используются. После отчёта — commit и обычный push в эту же ветку; без PR/merge, затем остановка перед TASK 03.
