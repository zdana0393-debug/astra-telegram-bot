## 2. Локальный воспроизводимый upgrade runner
Сделать `scripts/...` CLI, работающий исключительно с явным абсолютным ПУТЁМ ЛОКАЛЬНОГО SQLite файла и явным `--local-only`. Запрещены remote/D1 bindings, автоавторизация, сторонние URL/секреты, D1 execute remote, shell вызовы Cloudflare, default prod names. Не запускать команду из автоматических тестов по адресу реальных данных.
- Перед изменениями create/verify an **isolated** backup и отдельную restore-копию; integrity_check/FK/DDL/version проверка. Runner не должен автоматически перезаписывать входную baseline; использует вторую копию/выходной файл. Нужны dry-run/read-only plan+SHA/source paths. **Если backup не проверен, abort до миграций.**
- Шаги строго в order `src/02_SCHEMA.sql` только для новой пустой фиктивной2.0; затем `0021→0022→0023→0024→0025→0026→0027→0028→0029` на остановленных writes. Реализовать целостное выполнение SQL в SQLite native parser/exec, не делать naive split(';') в триггерах. Включать FOREIGN_KEYS там, где их наличие требуется; на каждом этапе сверять real objects/indexes/triggers, SQL definition, migration_done/read-only checks. Документировать все известные guards/ручные пост-steps (если есть); не подменять их фиктивными значениями.
- Применять отдельный SQL migration целиком/транзакционно, когда схема и SQLite допускают; если авторские файлы неидемпотентны/содержат BEGIN и внешнюю transaction нельзя безопасно обернуть, честно остановиться, предложить строго локальный пошаговый runner с журналом и валидированной точкой продолжения. Нельзя скрывать частичную миграцию через IF NOT EXISTS, отключать guards или назначать `migration_done=1` вручную.
- Manifest содержит source SHA256, ordered steps, counts and normalized DDL. CHECK schema/candidate compatibility; repeat on completed synthetic base has zero change to wallet/history. For restart after an injected crash, classify safe resume vs STOP accurately, без DROP tables/triggers и без форсированного ремонта.
- Есть **проект** Cloudflare/Wrangler runbook для будущей отдельной репетиции с новой D1 и Dedicated Telegram test bot, но **не исполняемый remote deploy**. Учитывать, что Cloudflare `wrangler d1 migrations apply` поддерживает транзакционное применение отдельных миграций/backup, а `d1 execute --file` исполняет SQL-файлы; требования к версии/каталогу миграций описать явно.
