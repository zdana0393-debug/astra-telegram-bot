## Инварианты и доверенная граница

Каждая операция — один SQLite INSERT с BEFORE/AFTER triggers. Полный statement либо фиксирует баланс, ledger, результат, флаги, либо откатывается. JS mutex и ручных BEGIN/COMMIT через D1 нет. Ledger содержит operation_id, idempotency_key, владельца, delta, reason, timestamp. Приглашённый связан nullable source_id в операции. Его удаление не отменяет уже заработанные реферером деньги и не оставляет его ID в ключе (ключ реферала случайный).

Исходный CHECK(balance>=0) остаётся. Рабочий код 2.1 изменяет balance только через операции; регистрация заносит стартовые 2 в ledger через trigger. Прямые ручные UPDATE баланса и старый Worker обходят этот контракт, поэтому запрещены совместные writers. Ledger — аудит приложения, не криптографическая защита от администратора БД. Контрольная сверка выявляет рассогласования; автоматически «чинить» деньги нельзя.

## Остаточные риски

Локальный SQLite, даже с восемью соединениями, не воспроизводит распределённые запросы/реплики, ограничения CPU/subrequests и SQL-совместимость production D1. До staging кандидат НЕ готов для production. Все чтения для принятия денежных решений должны идти на primary: не включать read replication/withSession без отдельной проверки.

Точный однократный эффект у Telegram недостижим без внешнего idempotency API. Повтор сохранённого расклада после таймаута может повторно показать тот же текст, но не списывает ещё раз. Аренды предотвращают обычные параллельные sends, но остановленный дольше аренды Worker может продолжить работу; возможны дубликаты внешних сообщений. Неопределённая рассылка может быть пропущена. Повторяемые неэкономические уведомления (приветствие, прогноз после знака, бонусное подтверждение) могут дублироваться после сбоя. Реферальное уведомление best-effort, само начисление атомарно.

Уже начатую отправку при параллельном /delete отозвать невозможно. Удаление не отзывает сообщения из Telegram и не удаляет Cloudflare backups; владелец отдельно определяет срок хранения резервных копий. После /delete новый /start вновь получает 2, как в 2.0; антифрод-идентификаторы не сохраняются тайно.
