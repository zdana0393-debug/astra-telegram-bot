## Только локальная копия

Сохранить свою отдельную копию SQLite до любых проб. Никакие персональные/платёжные копии не коммитить. Runner требует уже существующий локальный файл и не поддерживает remote-режим:

```sh
node --experimental-sqlite scripts/apply-tarot29-local.mjs \
  --local-only --database /absolute/path/to/isolated-copy.sqlite
```

Команда — для локальной копии, не для D1 и не для токена Cloudflare. Runner читает **целые** проверяемые файлы, не делит CREATE TRIGGER по точкам с запятой. Preflight проверяет фактические базовые DDL, отсутствие foreign partial29, канонические существующие тарифы, wallet/FK и flags новой продажиOFF. На каждый файл — локальный BEGIN IMMEDIATE/COMMIT с rollback при ошибке; это четыре транзакции, не единая общая транзакция через несколько файлов. Возвращаются имена файлов и SHA, без пользовательских строк.

При обрыве между файлами уже законченные шаги сохраняются, migration_done не открывает продажи. Повтор допустим только при совпадающих DDL и данных. При foreign definition, неполной исходной0026/28 или wallet mismatch — STOP. Никаких DROP/CHECK-removal/UPDATE balance ради ремонта. Это минимальный local runner только29; полный проверяемый upgrade из фактической оригинальной2.0 и cloud runner — TASK04.

`check_integrity_tarot25_29.sql` — read-only агрегаты: DDL drift всей ожидаемой схемы, тарифные данные, balance/ledger, paid↔offer↔ledger, generation, flagsOFF и FK. Выполнять только после полной0029 на локальной копии. Все violations=0; foreign_key_check без строк. Файл содержит quoted DDL с внутренними `;`: для него используется quote-aware reader `readOnlyStatements`, не строковый split(';').

## Восстановление и будущая приёмка

Перед будущей установкой:установить фактическую основу, пригодный backup, отдельное восстановление, сравнение каждого баланса/ledger/старого текста и новых предложений/paid proof; остановить writers. Нельзя смешивать восстановленную БД со старыми незавершёнными входящими событиями без сверки. 0029 не является процедурой починки испорченной0026.

При сбое предпочесть совместимое исправление вперёд, с закрытой новой продажей. Полный restore — только после проверки всех событий после backup: новые оплаченные результаты/ledger/возвраты/отзывы нельзя терять ради отката.
