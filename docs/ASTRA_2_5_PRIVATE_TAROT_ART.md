## Что реализовано

`scripts/import-tarot-art-private.py` читает только данные ZIP, а не инструкции внутри него. С `--manifest` проверяет явный формат `astra-author-art-assets-v1`,78 уникальных ID/asset_id, точные пути `cards/<card_id>.jpg`, обязательные JPEG SHA256, размеры/ориентацию и обе части как единый набор. Дубли между ZIP, пропуски, лишние/опасные файлы, links/спецфайлы/шифрование, повторные JSON-ключи и превышение лимитов закрывают импорт. Не использует `extractall`. Прежний односоставный режим с embedded manifest и `cards[].file` сохранён для совместимости; поля optimized/PNG не смешиваются.

Входные JPEG копируются побайтово неизменными в `inputs/` нового закрытого каталога **вне Git**. Все78 поступивших JPEG уже нужного размера и без EXIF/ICC/comment: прямые версии также скопированы побайтово, без второй компрессии. Перевёрнутые — ровно180°, JPEG quality95/subsampling0 для сохранения деталей после перекодирования. Размеры сохранены; maxRMSE2,468/255. Перевёрнутый JPEG перекодируется, поэтому его пиксели немного отличаются от точного поворота декодированного входа. В прежнем режиме остаются нормализация EXIF/прозрачности/размера. Сохраняются156 файлов, SHA256 входов/производных и приватные manifests. Лица не генерируются и не ретушируются. Каталоги0700, файлы0600; output должен быть новым. При ошибке промежуточные файлы убираются.

Повторяемый локальный импорт в **новый** приватный output, без сетевых действий:

```sh
python3 scripts/import-tarot-art-private.py --local-only \
  --manifest /absolute/private/manifest.json \
  --archive /absolute/private/Astra_Tarot_78_Codex_Part_01_of_02.zip \
  --archive /absolute/private/Astra_Tarot_78_Codex_Part_02_of_02.zip \
  --output /absolute/private/new-astra-deck
```

Фактическое расположение приватных файлов сообщается владельцу отдельно; в Git публикуются только код/тесты/агрегированные результаты. Черновик приватного Telegram-реестра содержит78 записей/156 файлов, `bot_id`, `realm`, `file_id` пока null. Он намеренно не проходит validation сборщика до отдельно разрешённой настоящей загрузки.

`.gitignore` исключает новые изображения/ZIP и очевидные приватные каталоги. Это дополнительная защита: Git `-f` может её обойти, поэтому основное правило — **физически вне репозитория**. Старые уже отслеживаемые технические screenshots сохранены. Ни приватный Worker, ни настоящий реестр file_id, ни авторский manifest нельзя добавлять в публичный Git. ## Бесплатное приватное хранение и доставка

Предлагается закрытый Telegram-канал без публичного username/ссылки или личный чат владельца с ботом. После отдельного разрешения один раз загрузить156 подготовленных JPEG **тем же ботом**, который будет их отправлять. В каждой записи связать `card_id`, orientation, SHA256 производной и ответ `sendPhoto`. Хранить последние пригодные `photo[].file_id`, а не `file_unique_id`. Перед регистрацией сверить изображение, имя/ориентацию и источник запроса; один ответ Telegram сам по себе не доказывает соответствие картинки карте. Публичный URL, GitHub Pages, R2, KV и image-BLOB в D1 не требуются.

Файл реестра — приватный JSON вне Git, режим0600. Структура:

```json
{
  "version": "astra-telegram-art-v1",
  "deck_version": "rws78-v1",
  "art_version": "astra-author-art-v1",
  "bot_id": 123456,
  "realm": "production",
  "source_manifest_sha256": "64 строчных hex-символа SHA256 исходного manifest",
  "cards": [
    {"card_id":"major-00","upright":{"file_id":"ID_ОТ_ЭТОГО_БОТА"},"reversed":{"file_id":"ДРУГОЙ_ID_ОТ_ЭТОГО_БОТА"}}
  ]
}
```

В настоящем реестре ровно78 записей и156 разных file_id. Пример выше — описание структуры, не готовый реестр. Тестовые `SYNTHETIC_*` в fixtures не являются рабочими Telegram IDs. Официальное назначение `file_id` — повторное использование этим же ботом; IDs другого бота/realm не переносить. Проверить bot_id через отдельно разрешённый getMe, без передачи token в чат/логи. Одноразовая загрузка/получение настоящих IDs **здесь не выполнялась**; инструмент сетевой загрузки не реализован и не подразумевается этой подготовкой.

`scripts/build-tarot-art-private.mjs` проверяет реестр и точный SHA неизменённого TASK07-кандидата и создаёт новый single-file **вне Git**:

```sh
node scripts/build-tarot-art-private.mjs --local-only \
  --registry /absolute/private/telegram-registry.json \
  --output /absolute/private/new-astra25-worker.mjs
```

Реестр встраивается в частный код Worker, не в публичный маршрут. Это позволяет обойтись без дополнительного cloud storage и новых SQL-таблиц. Source/code download доступен администраторам Cloudflare: доступ к аккаунту должен быть ограничен владельцем. Сборка не включает файлы изображений, Bot token или лица. Сборщик запрещает Git-пути, links/hardlinks реестра, небезопасные права и перезапись файла. Существующие release-файлы не меняются. Новая env `ASTRA_TAROT_ART_ENABLED` **OFF по умолчанию**. Bot token prefix/realm сверяются до использования file_id; реальные getMe/валидность IDs остаются NOT_TESTED. Ни продажи, ни Stars/экономика/рассылка этим flag не активируются.

Telegram — внешний оператор, бот-чаты не имеют сквозного шифрования. Лицо будет видно получателям раскладов; `protect_content:true` ограничивает стандартное сохранение/пересылку, но не скриншоты/фотографирование. Это приватное хранение оригиналов и отсутствие публичного image-hosting, **не обещание секретности уже выданных карт**. Хранить частную офлайн-копию оригиналов, производных и реестра; нельзя обещать бессрочное хранение Telegram или незаменимость file_id. При недоступности остаётся текст.

## Финансовая безопасность и совместимость

`src/tarot25/art-delivery.mjs` не импортирует генератор карт или платежи, не изменяет D1 и не создаёт покупок. Использует только сохранённые snapshot.cards/reversed/position_id и versioned reader. Нет повторного draw или изменения оплаченного текста. Сборщик связывает реальные callback/ownership/атомарные адаптеры TASK07 с этим презентационным модулем.

Порядок покупки: прежнее подтверждение цены → прежний атомарный confirmPurchase → прежняя доставка полного текста → только при `sent` и ненулевом HTTP новая проверка владельца/поколения SQL → одна попытка отправить альбом. В альбоме2…10 карт в исходном порядке; карта дня идёт `sendPhoto`. Текст не помещается в ограниченную1024-символьную подпись: остаётся отдельным с прежним разбиением и навигацией; подпись содержит только номер/название/ориентацию. Ответы фото требуют настоящих message_id/chat/photo, альбом — полного количества уникальных ACK. HTTP200 с `result:true` не означает успех.

400/403/429/5xx, сетевой сбой, неопределённый ACK, ошибка D1 или нехватка invocation budget не меняют сохранённый расклад, баланс или ledger. При неизвестном результате фото возможен фактический приём Telegram: **автоматического повтора нет**, даже на429. Повторный callback покупки не отправляет новый альбом. Явное бесплатное чтение в истории отправит тот же текст/альбом; может получиться дубль ранее принятой фотографии. Фото-ACK/ошибки **не образуют отдельный долговечный журнал** и не дают exactly-once гарантии. Не добавлять скрытые SQL-состояния в финансовую таблицу. Следующая отдельная проверка Telegram должна определить удобство ожидания после429; автоматическая очередь медиа сейчас не предлагается.

При перечитывании длинного текста альбом добавляется только на первой странице, не на каждом продолжении. Старые3/5✨ содержали только текст без canonical78 snapshot: они открываются бесплатно и побайтово прежними, без выдуманного восстановления карт по словам. Историческую колоду/ориентацию не угадывать.

Карта дня **остаётся прежней бесплатной картой из22 Старших арканов**. Используются ровно существующие hash `card|id|MSK_day`, `flip|id|MSK_day` и выбор из прежнего TAROT; имя сверяется с явным ID-контрактом. Одна московская дата передаётся тексту и изображению, в том числе около полуночи. Переход бесплатной карты дня на78 карт был бы отдельным изменением механики и здесь не выполнен. Непосредственно перед отправкой проверяется действующий профиль/generation; /delete и старые callbacks не открывают прежнюю покупку. Запрос, уже находящийся в Telegram в момент удаления, отозвать атомарно с D1 нельзя.
