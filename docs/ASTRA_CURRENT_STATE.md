# Фактическое состояние локального кандидата

Дата: 4 ноября 2026. Текущая ветка: astra-2.2-shell, созданная на основе astra-2.1-hardening (a3a02f2). Новое ТЗ уже было добавлено владельцем в удалённую ветку 2.2 и сохранено. Цель — исключительно тестовый Worker astra-staging-21-worker и база astra-staging-21, binding DB.

## Реализовано локально

- Astra 2.1 сохранена в release/ASTRA_2_1_WORKER.js, исходный src/ не менялся.
- Готовый single-file 2.2: release/ASTRA_2_2_WORKER.js. Шесть направлений, подменю/назад/домой, художественная справка, методология, команда, FAQ, фактическое досье и заглушки будущих служб.
- Миграция 0022 и четыре небольших шага для Console: отдельная однократная награда GPT6 +5 с ledger, атомарным rollback и удалением при FK OFF. Исходные операции/CHECK/триггеры 2.1 не меняются.
- Сохранены бонусы и цены, бесплатное число дня и тексты, Europe/Moscow, DB, webhook secret checks, финансовые повторы и Cron. Новый путь покупки имеет подтверждение, старые callback_data работают. BOT_USERNAME настраивается обычной переменной для тестового бота.
- На Node 24.22.1 пройдены исходные 30 assertions, регрессия 30 и hardening 28 на 2.1; те же 30+28 на 2.2; 20 новых тестов. Команда sh scripts/test-2.2.sh. Telegram замокирован, SQLite локальный. Подробности в ASTRA_2_2_TEST_REPORT.md.

## Не выполнено/не реализовано

Миграция 0022 не запускалась на удалённой D1, Worker 2.2 не деплоился, webhook/Cron settings и секреты не менялись. Реальное состояние staging и production не проверялось. Production со слов владельца остаётся работающей Astra 2.0.

Не реализованы будущие 2.3–3.0: новый контент гороскопа, расширенный прогноз, изменение экономики, 78 карт, анкеты/портрет, совместимость, настоящая натальная карта/лунные вычисления, Stars, коллекции и графика. Текстовые разделы прямо отмечают подготовку; денег за них не берут.

Следующий шаг владельца: ревью ветки 2.2 с base=astra-2.1-hardening, backup и ручная проверка/установка только на staging по ASTRA_2_2_STAGING_GUIDE.md. Не применять старую инструкцию 2.0 поверх схемы ledger. Не сливать main и не менять рабочего бота автоматически. Публикация ветки/наличие PR указываются отдельно в итоговом отчёте; локальные тесты не являются доказательством деплоя.
