## Выбор и три правила совместимости

Восьмидневная редакционная ротация темы и seed sign/day/locale/engine_version сохранены. В каждом из шести разделов выбирается строго своя стихия и собственный ракурс знака с действительной модальностью. Два раздела получают явное дополнение модальности, позиции чередуются; это позволяет использовать весь банк без превышения длины. Независимые выборы разделов не связывают все ракурсы в один повторяющийся шаблон. Это символический общий солнечный прогноз, не персональный расчёт эфемерид.

1. `timing:commit/observe`: ограниченный шаг против предварительного наблюдения/паузы перед окончательным решением.
2. `contact:open/quiet`: инициирование контакта против пространства для тишины. Проверяется и за пределами отношений.
3. Явные `incompatible_with` для 10 прочитанных пар, повторяющих одну мысль внутри абзаца. Например, три вариации смены ритуала у Тельца и двойное объяснение «термин ещё не понимание» у Близнецов больше не соединяются.

Нейтральная запись может не нести директивы. Фильтр работает перед выбором; validator независимо отвергает противоположные полярности и запрещённые пары. Тесты строят конфликт из настоящих записей **в рамках одной темы**: это дополнительные правила, не переименование доминанты. Исчерпывающая семантическая онтология не заявляется. ID всех выбранных слоёв и директивы записываются в существующий JSON source_tags, без изменения схемы D1.

## Воспроизводимый аудит и его ограничения

**sh scripts/test-2.3b.sh** извлекает исходный single-file через `git show e9cff2b:release/ASTRA_2_3B_WORKER.js` во временный файл и передаёт его `scripts/audit-forecast.mjs`. Исходный и новый генераторы запускаются на одинаковых входах, без сети и ручного редактирования результатов. Для отдельных прогонов аудит принимает путь к такому JS. Требуется история Git с исходным коммитом; при её отсутствии тест останавливается, а не выдаёт пустое сравнение за успех.

Набор: **1 826 дат × 12 знаков = 21 912 выдач на каждую редакцию**, 2026-01-01…2030-12-31. У каждого результата сверено прежнее число с исходным hash 2.3A, повторная детерминированная генерация, обязательные разделы, длина, теги и отсутствие заданных опасных/ложно астрономических паттернов. Запретные паттерны и зарегистрированные конфликты: 0. Бесплатный текст **198–245 русских слов**, лимит 160–260 сохранён. Максимум free **1974 UTF-16 / 3636 UTF-8 bytes**, extended **2615 / 4820**. Лимит Telegram проверяется по UTF-16, не по байтам.

Абзацы сравниваются отдельно по разделам, без заголовков, в нижнем регистре, ё→е, без пунктуации. Число дня намеренно не включается в показатель разнообразия шести абзацев: у него всего девять честно фиксированных значений.

### Близкие конструкции и фрагменты: улучшение не равнозначно отсутствию повторов

Отдельная выборка 90 последовательных дат **2026-11-01…2027-01-29**, все 12 знаков. Триграммы точных нормализованных слов сравниваются по Jaccard, порог 0,45. Без лемматизации, без LLM, без заявления о полном семантическом анализе. Длинный общий фрагмент может дать высокую близость при разных выводах; одинаковый смысл другими словами может пройти ниже порога.

| Близкие пары абзацев | e9cff2b | Hardening |
|---|---:|---:|
| Соседние дни одного знака | 0 / 6408 | 0 / 6408 |
| Все пары одного знака с расстоянием до 30 дней | 5358 / 160920 | 8094 / 160920 |
| Все пары одного знака внутри 90 дней | 11206 / 288360 | 16650 / 288360 |
| Разные знаки на одной дате | 1273 / 35640 | 0 / 35640 |

**Близость на 30/90 днях выросла, хотя точных дублей стало меньше.** Новый текст разделяет устойчивые элементные фрагменты; увеличенное число комбинаций не делает их новыми смыслами. Краткие предложения ракурсов повторяются между темами — соседняя фразовая повторяемость также слегка выросла. Это открытый редакционный риск, а не скрытый успешной метрикой результат.

Дополнительно сравниваются ID исходного элементного фрагмента и сочетание «фрагмент + ракурс знака», игнорируя добавку модальности. Через 30 дней у нового корпуса повтор исходного фрагмента есть у всех **129 312 / 129 312** оцениваемых абзацев: доминанта возвращается каждые 8 дней. Сочетание фрагмента с тем же ракурсом возвращается в **92195 / 129 312** случаях; в 90-дневном окне — **123137 / 124 992**. Комбинаторное разнообразие не следует выдавать за бесконечную содержательную новизну.

В METRICS также считаются явно описанные риторические конструкции: противопоставление/различение, вопрос и образ ресурса/границы. Это перекрывающиеся поисковые категории по regex, не измерение «уникальных смыслов». Повторяющийся приём различения составляет заметную часть корпуса; он соответствует сдержанной интонации, но остаётся предметом редакционной приёмки.

Составные 12 прогнозов одной даты, четыре даты Девы и оба расширения прочитаны и обновлены. Десять обнаруженных внутритекстовых эхо вынесены в ограничения. Образцы в **ASTRA_2_3B_EDITORIAL_SAMPLES.md** — прямой вывод текущего генератора; тест сверяет free, paid, число, версии и source_tags исходников с собранным Worker на 48 входах. Это редактура исполнителя, **не независимая приёмка владельца** и не доказательство отсутствия близких смыслов во всём банке.

## CPU, D1 и дальнейшая безопасная приёмка

Single-file: **525,271 bytes**, исходный — 305 474; рост ~72.0%. Локальная диагностика Node: создание/валидация/structuredClone каталога + первый прогноз, 30 образцов, median **2.028 ms**, p95 **3.271 ms**; тёплая генерация 500 образцов, median **0.039 ms**, p95 **0.101 ms**. Это wall-clock одного Node-процесса: нет разбора JS в новом Cloudflare isolate, HTTP/webhook, D1, Telegram или восьмиадресного Cron. **Не доказано соответствие 10 ms CPU Workers Free и отсутствие 1102.** Числа локальной диагностики зависят от машины/нагрузки, не являются платформенным SLA.

Средний cache payload **8533 bytes**, paid payload **5284 bytes**: примерно 37.4 MB/год на 12 общих ru-строк в день и 192.9 MB/год при 100 покупках/день дополнительно, до ledger/индексов/SQLite/backup. Сведения review: Workers Free 10 ms CPU HTTP/Cron; D1 Free 5M rows_read/day, 100K rows_written/day, 5 GB; enforcement с 01.09.2026. Официальные страницы ранее блокировались прокси; здесь эти квоты не проверены независимо и реальный тариф не исследовался.

**Владельцу перед дальнейшим внедрением:** принять тексты и ограничения повторяемости; проверить актуальные квоты; отдельно разрешить только staging-процедуру из STAGING_GUIDE; сохранить backup/версию и проверить имена **astra-staging-21-worker / astra-staging-21**. Затем измерить холодный/тёплый CPU, 1102 и D1 rows_read/rows_written по каждому сценарию, включая Cron, повторную покупку и доставку. Таблица протокола пока «не измерено»; локальный SQLite не заменяет эти результаты. До повторного review ни один Worker не развёртывать.

Существующий кэш не очищать и оплаченные снимки не удалять. Дальнейшие расширения корпуса — содержательные новые версии после приёмки, без искусственных парафразов и без обещания уникальности на десятилетия. Exactly-once внешней доставки нет; один платёж/сохранённый результат не устраняют возможный повтор Telegram-сообщения. Production, webhook, cron-настройки, секреты и main в этой задаче не менялись.
