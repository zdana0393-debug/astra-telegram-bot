# Astra 2.3B: инструкция для начинающего владельца Cloudflare

**Сейчас ничего не устанавливалось.** Это подготовленный порядок ручной проверки после ревью. Только тестовый **Worker astra-staging-21-worker**, база **astra-staging-21**, binding **DB**, отдельный тестовый бот. Не выбирать основной opel-astra-bot, astra-live-v2, основной Telegram-бот или main. SQL/deploy/webhook/секреты Codex не выполняет.

## 1. До любых изменений

1. Просмотрите Draft PR astra-2.3b-forecast-engine → astra-2.3-editorial. Откройте EDITORIAL_SAMPLES, TEST_REPORT и ARCHITECTURE с этим префиксом ASTRA_2_3B. Тексты — реальные результаты генератора; подтвердите их качество отдельно от зелёных тестов.
2. Проверьте официальные актуальные D1 Limits/Pricing по ссылкам из архитектуры. Из этой среды доступ к ним блокировался; действующие квоты и включённый тариф не подтверждены. Не считайте большой архив гарантированно бесплатным.
3. Cloudflare Dashboard → Workers & Pages → **astra-staging-21-worker**: сохраните активный JS 2.3A и номер deployment, имя тестового бота, существующий DB-binding и настройки. Не копируйте секреты в чат/репозиторий. Тестовый Worker должен использовать собственные уже установленные секреты; новых секретов 2.3B не требует.
4. D1 → **astra-staging-21**: создайте резервную копию штатным способом и убедитесь, что она восстанавливается в отдельной тестовой копии. Сохраните агрегаты `SELECT count(*) AS users,coalesce(sum(balance),0) AS balance FROM astra_users;`. Не экспортируйте production. Должны уже существовать полные схемы 0021 и 0022: 0023 предназначена поверх них и 2.3A, не поверх пустой базы.
5. Согласованно поставьте **только тестовый Worker** на паузу. Допустимый файл — release/ASTRA_2_1_MAINTENANCE.js, он отвечает 503 и не пишет из Cron. Дождитесь завершения начатых запросов. Webhook и расписание Cron не перенастраивать, очередь не сбрасывать. Не затягивать паузу: повторная доставка Telegram ограничена во времени.

## 2. Миграция 0023 через браузер

6. В Storage & databases → D1 → **astra-staging-21** → Console проверьте имя базы ещё раз. Сначала выполните по одному запросы scripts/check_integrity.sql: расхождений быть не должно.
7. По очереди откройте, целиком скопируйте и выполните отдельными нажатиями Execute:

   1. migrations/0023_steps/01_daily.sql — анонимный кэш и индекс даты;
   2. 02_unlocks.sql — оплаченные снимки и индекс даты;
   3. 03_guard.sql — проверка профиля, даты, цены и баланса;
   4. 04_post.sql — атомарные −4 и ledger;
   5. 05_erase.sql — очистка при /delete, включая FK OFF;
   6. 06_cache_immutable.sql — запрет UPDATE сохранённого общего прогноза;
   7. 07_unlock_immutable.sql — запрет UPDATE оплаченного снимка.

   Каждый CREATE TRIGGER копировать с BEGIN…END целиком, не делить по внутренним `;`. Если Console не принимает два оператора в первых файлах, выполните CREATE TABLE целиком, затем отдельный CREATE INDEX; trigger не делить. migrations/0023_forecast.sql — точная конкатенация тех же шагов для инструментов, поддерживающих весь файл; выполнять оба варианта не нужно.
8. При ошибке или «No SQL statements detected» оставьте паузу: проверьте, что вставлен SQL без Markdown-ограждений и весь отдельный оператор. Не снимайте CHECK, не создавайте фиктивные tarot-платежи и не исправляйте balance вручную. IF NOT EXISTS позволяет повторить тот же шаг после выяснения причины; оно не заменяет уже существующий неправильный DDL другой редакции.
9. Выполните по одному запросы scripts/check_integrity.sql и scripts/check_integrity_2_3b.sql. Все mismatch/orphan-показатели должны быть 0, список дат с более чем 12 кэшами — пустым, foreign_key_check — пустым. До покупок paid_rows=0 (sum может быть NULL). Сама миграция не меняет балансы и не создаёт подарков. Сравните users/сумму balance с предыдущим снимком.

## 3. Дата включения и готовый JS

10. Worker → Settings → Variables and Secrets: добавьте обычную **Text** переменную **ASTRA_FORECAST_START_DAY**, значение `YYYY-MM-DD` — следующая дата **по Москве**. Например, если по Москве сейчас 06.11.2026, значение 2026-11-07. Это не секрет. Не использовать пример вслепую, если день уже другой. После начала работы не переносить этот порог вперёд; дальнейшие версии сохраняют его.
11. Проверьте прежнюю Text BOT_USERNAME: фактический username тестового бота без @. DB остаётся **astra-staging-21**, секреты тестового бота остаются прежними. Пропущенная/некорректная ASTRA_FORECAST_START_DAY намеренно делает /health и webhook 503, Cron не пишет.
12. Edit code только **astra-staging-21-worker**: заменить ВСЁ содержимое JS файлом **release/ASTRA_2_3B_WORKER.js**. Не склеивать с 2.3A. Это самостоятельный ES module без npm/сборки для владельца. Сборка для разработчика уже выполнена локально: node scripts/build-2.3b.mjs.
13. После отдельного решения владельца нажать Deploy тестового Worker. Проверить active deployment и `/health` его адреса: version ASTRA-2.3B-candidate, ready=true, schema_ready=true. Это только структурная готовность: требуется дальнейший smoke test.
14. Не открывать /activate, не запускать setWebhook, не менять /telegram-webhook, secret header, allowed_updates и Cron settings. Существующая тестовая конфигурация остаётся. Если тестовый webhook отсутствует, его настройка — отдельная задача владельца, не часть этого релиза.

## 4. Что проверить с телефона

15. До даты включения бесплатный прогноз остаётся редакцией 2.3A, расширенный не продаётся. Это осознанный переход: старый free раньше не сохранялся в D1, поэтому нельзя обещать восстановление его прежней строки после смены редакции. С полуночи Москвы все бесплатные входы, выбор знака и Cron используют новый единый кэш.
16. Откройте новый бесплатный прогноз со старой кнопки, из меню и после выбора знака на собственном тестовом профиле. Должны быть дата/зона/знак, тема, отношения, работа, финансы, эмоциональный ритм, число со смыслом и итог. Повтор одного знака/даты дословен. При балансе 0 всё это бесплатно.
17. «Расширенный — 4 ✨» показывает подтверждение: само открытие/«Назад» не списывает. Подтвердите на тестовом профиле с достаточным балансом: один расход −4, отдельный материал с символом/цветом, дополнением числа, руной и Советом Жирного. Нет точной Луны, Stars, процентов точности или микропокупок.
18. Повторите подтверждение из другого сообщения и «Повторить расширенный»: тот же текст, баланс без второго расхода. Старое подтверждение после полуночи не покупает прошлый день; если за ту дату уже куплено, оно открывает сохранённый архив. Новая дата допускает новый заказ. При недостатке 4 ✨ результат не продаётся, free остаётся.
19. Проверьте прежние Таро −3, карту дня, бонус +1, реферал +5, канал +5 (если тестовая проверка настроена), GPT6 +5 один раз, /privacy, /stop, шесть направлений и навигацию. Проверку /delete проводить только на собственных тестовых профилях; снимки другого профиля и общий анонимный кэш должны сохраниться.
20. На staging отдельно проверить независимые Worker invocations, повторы доставки, лимиты CPU/subrequests, errors при квотах D1 и rows_read/rows_written в meta. В scheduled handler по-прежнему до восьми получателей; рассылается только бесплатный общий прогноз. Повтор сообщения при неопределённом сетевом исходе возможен, второе списание — нет.
21. Повторить оба контрольных SQL-файла. Не публиковать настоящие ID, результаты других людей, backup и секреты в скриншотах или чате.

## 5. Ошибка, откат и хранение

При ошибке — maintenance JS тестового Worker, сохранить БД/диагностику для расследования без утечки токенов. Не удалять новую схему или снимки. Полная 0023 совместима с прежним Worker **2.3A** на уровне ledger/SQL: при возврате его JS интерфейс расширенных прогнозов исчезнет до исправления, данные и начисления сохранятся; SQL-cleanup остаётся действующим. Не откатывать на исходный 2.0 поверх ledger-схемы и не восстанавливать старый backup поверх новых оплат без отдельной сверки. После исправления 2.3B читает прежние снимки без новой оплаты.

Не очищать оплаченный архив ради экономии места. При росте базы сначала измерить объём и согласовать retention/перенос/тариф. Анонимный free-cache также не удаляется автоматически: его изменение меняет обещание долговечности. Production и main эта процедура не затрагивает.
