# Astra 2.1 — подготовка обновления (без деплоя)

**Это рабочая копия кода Astra 2.0 для подготовки безопасного обновления 2.1. Она не связана автоматически с рабочим Cloudflare Worker.**

## В каком порядке читать

1. `00_НАЧНИ_ЗДЕСЬ.md` — базовая инструкция.
2. `01_CODEX_ЗАДАНИЕ_ASTRA_2_1.md` — полный запрос для Codex. Использовать целиком.
3. `docs/ASTRA_2_1_АУДИТ_И_ПЛАН.md` — известные проблемы текущей версии.
4. `src/01_ASTRA_V2.js` — существующий исходник, с которого начинаем.
5. `docs/ASTRA_3_0_SPEC_v0_2.md` — задумка будущих версий, **не** уже готовые функции.

## Локальные тесты

С Node.js 22+ выполнить из корня репозитория:

```bash
node --experimental-sqlite src/03_LOCAL_TEST.mjs
```

Для этой задачи достаточно локальных тестов. Токены, D1 и интернет-доступ к Telegram **не нужны**. Codex создаёт новую схему и проверяет её на локальных фиктивных данных.

## Правила безопасности

- **Никакого деплоя, миграций на живой D1, вызовов `setWebhook`, реальных платежей или доступа к живому боту.**
- Не записывать секреты в GitHub, документацию, скриншоты или сообщения чата.
- Настоящие `ASTRA_BOT_TOKEN`, `ASTRA_WEBHOOK_SECRET`, `ASTRA_ADMIN_KEY` остаются в Cloudflare Workers Secrets.
- Binding `DB` — привязка D1 в Cloudflare, а не переменная для Codex.
- Не создавать здесь публичных `.env` с реальными значениями, даже если GitHub-репозиторий приватный.
- Использовать ветку / pull request для правок Codex; проверять diff и тесты до объединения.

Локальная реализация: `release/ASTRA_2_1_WORKER.js`. Исходный `src/` сохранён как снимок 2.0. Полный запуск тестов: `sh scripts/test.sh` (Node.js 22+).
