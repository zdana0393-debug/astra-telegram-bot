## 1. Цели и рамки проекта

Наша задача — сделать **доступный на бесплатных тарифах** Telegram-бот с гороскопом по солнечному знаку, картой дня, раскладами Таро, рассылками, внутренней звёздной валютой и реферальной системой. После стабильного запуска — расширить до 78 карт, астрономически обоснованных входных данных, натальной астрологии, лунного календаря, нумерологии, подборки камней и рун. Подписку на канал и бонусы за неё добавлять только при наличии соответствующего канала и прав у бота.

**Известное из предыдущих попыток:** бот в Telegram создан; Cloudflare-аккаунт и Worker существуют; база D1 `astra-db` создана; таблица `users` однажды отображалась в интерфейсе; возникала ошибка `Missing: DB`. Это говорит лишь о проблеме конфигурации или доступа, а не доказывает работоспособность/неработоспособность текущего проекта. В новом запуске сначала проверить реальную привязку `DB` в выбранном Worker и отдельно выполнить `SELECT 1` через `env.DB`.

**Базовый MVP:** /start; регистрация по дате рождения или выбор знака; меню; общие гороскопы 12 знаков; карта дня с неизменностью в рамках локальной даты; расклад из 3 карт; сохранение истории; опциональные рассылки; базовый журнал звёзд; проверенный webhook. **Не обещать** натальную карту без геоданных, времени и валидированного движка домов.

## 2. Архитектура знаний

Для каждого прогноза различаем три слоя: **входные данные** (факты/расчёты), **правила интерпретации** (выбранная традиция) и **текст пользовательского сообщения**. Их смешение приводит к красивым, но неподдающимся проверке ответам.

В астрологии планета отвечает на условный вопрос «что проявляется», знак — «каким образом», дом — «в какой сфере», аспект — «как взаимодействуют функции». В Таро карта определяет архетип, позиция расклада — его роль, вопрос — контекст, а синтез расклада — связи и противоречия между картами. Для нумерологии сохраняем точный алгоритм приведения чисел, для камней — название традиции соответствий.

## 3. Западный зодиак: определения и правила

В тропическом зодиаке отсчёт ведётся от точки весеннего равноденствия; 360° делятся на 12 секторов по 30°. Поэтому тропический астрологический знак — **не** тождественен фактическому созвездию на небе. Сидерические варианты — отдельная система; не смешивать её с тропической без переключателя и пояснения.

**Стихии:** Огонь (Овен, Лев, Стрелец) — инициатива, воля, вдохновение; Земля (Телец, Дева, Козерог) — практичность, устойчивость; Воздух (Близнецы, Весы, Водолей) — коммуникация, идеи; Вода (Рак, Скорпион, Рыбы) — эмоциональность, интуиция. Это архетипы, а не доказанные свойства людей.

**Модальности:** кардинальные знаки инициируют (Овен, Рак, Весы, Козерог), фиксированные удерживают (Телец, Лев, Скорпион, Водолей), мутабельные адаптируют (Близнецы, Дева, Стрелец, Рыбы). Комбинируя стихию и модальность, можно писать более разнообразные интерпретации — например, фиксированный Огонь Льва и мутабельный Огонь Стрельца.

**Управители:** Марс — Овен и традиционно Скорпион; Венера — Телец, Весы; Меркурий — Близнецы, Дева; Луна — Рак; Солнце — Лев; Юпитер — Стрелец и традиционно Рыбы; Сатурн — Козерог и традиционно Водолей; современные соуправители: Плутон — Скорпион, Уран — Водолей, Нептун — Рыбы. Таблица в `data/astrology_reference.json` фиксирует обе системы.

**Эссенциальные достоинства:** обитель (домициль) и экзальтация — традиционные статусы планеты в знаке; изгнание и падение — противоположные позиции. В классической семипланетной схеме экзальтации: Солнце в Овне, Луна в Тельце, Меркурий в Деве, Венера в Рыбах, Марс в Козероге, Юпитер в Раке, Сатурн в Весах. Не присваивать древние достоинства автоматически Урану, Нептуну или Плутону.

**Пограничные даты:** календарные интервалы в таблицах приблизительны. Для точного определения солнечного знака на границе необходима геоцентрическая тропическая эклиптическая долгота Солнца, рассчитанная для UTC-момента рождения.

## 4. Планеты и дома: как читать сочетания

Солнце — личность и воля; Луна — эмоции и потребность в безопасности; Меркурий — мышление и общение; Венера — ценности и привлекательность; Марс — действие; Юпитер — расширение; Сатурн — ответственность; Уран — перемены; Нептун — идеализация; Плутон — трансформация.

Например, **Марс в Овне** символизирует быстрый прямой импульс; **Марс в Тельце** — медленное, устойчивое действие; **Марс в Деве** — точную практическую работу; **Марс в Козероге** — дисциплинированную стратегию; **Марс в Рыбах** — действие через воображение, сочувствие и вдохновение. Результат интерпретации — возможная тема, а не обязательная черта характера.

**Дома** задают контекст: I — личность; II — ресурсы; III — ближайшее окружение; IV — корни; V — творчество; VI — повседневные обязанности; VII — партнёрства; VIII — общие ресурсы; IX — философия и дальние горизонты; X — карьера и общественная роль; XI — друзья и группы; XII — уединение и скрытые процессы.

**Пример объединения:** Венера (ценности и привязанности) + Скорпион (глубина и интенсивность) + II дом (ресурсы и самоценность) + квадрат к Сатурну (напряжение между желанием и ограничением) = тема доверия, личных границ и ощущения собственной ценности. Интерпретация должна учитывать остальную карту; одиночное сочетание не даёт категоричного прогноза.

**Системы домов:** Whole Sign, Equal Houses, Placidus, Koch, Regiomontanus, Campanus. Whole Sign удобно для первого расширенного модуля; Placidus более распространён в современной западной астрологии, но сложнее технически и может иметь проблемы в высоких широтах. В пользовательском профиле хранить `house_system` и версию алгоритма.

**Углы:** ASC (Асцендент) — характер внешнего самопроявления; DSC — партнёрство; MC — общественная реализация; IC — дом и корни. Асцендент, MC и дома **нельзя надёжно получить** только по дате рождения. Нужны точное время, исторический часовой пояс и координаты места рождения.

## 5. Аспекты: математика и трактовка

**Соединение 0°** — интеграция/усиление; **секстиль 60°** — возможность; **квадрат 90°** — напряжение; **трин 120°** — согласованность; **оппозиция 180°** — полярность. Дополнительно: квиконс 150°, полусекстиль 30°, полуквадрат 45°, сесквиквадрат 135°. Орбисы в JSON — **проектные настройки**, не универсальные догмы.

Для долгот λ₁ и λ₂ минимальная угловая разность: Δ = min(|λ₁−λ₂|, 360−|λ₁−λ₂|). Аспект с углом α считается найденным, когда |Δ−α| ≤ орбис. Например, 24° и 118° дают Δ=94°, то есть квадрат с отклонением 4° при орбисе 6°.

Важное дополнение: «применяющийся» и «расходящийся» аспект нельзя правильно определить только по расстоянию. Нужна информация о движении планет относительно точного аспекта во времени.

## 6. Полноценная натальная карта

Алгоритм: (1) преобразовать локальную дату/время в UTC по исторической зоне; (2) получить координаты места рождения; (3) рассчитать геоцентрические тропические эклиптические долготы; (4) вычислить углы и куспиды домов выбранной системой; (5) определить положения в знаках/домах; (6) вычислить аспекты и конфигурации; (7) собрать темы; (8) сформировать связную, некатегоричную трактовку с предупреждением об ограничениях.

**Условный пример карты:** Солнце во Льве в X доме — тема самореализации через публичную роль; Луна в Рыбах в V доме — эмоциональная вовлечённость в творчество; Меркурий в Деве в XI — аналитический вклад в общие проекты; Венера в Раке в IX — ценность эмоциональной связи и расширения кругозора; Марс в Овне в VI — энергичный подход к задачам; ASC в Скорпионе — сдержанное впечатление и наблюдательность. Все положения здесь вымышленные, это демонстрация метода.

**Дополнительные показатели будущих версий:** истинные и средние лунные узлы, ретроградность, Хирон, чётко определённая Лилит, Парс Фортуны, стеллиумы, Большой трин и Т-квадрат. Их значения и способы расчёта зависят от астрологической школы. Без определения варианта алгоритм не включать.

## 7. Гороскопы: три уровня точности и один текстовый движок

**Уровень A:** массовый солнечный гороскоп, опирающийся на выбранную традицию и редакторскую библиотеку. **Уровень B:** тот же гороскоп с рассчитанными астрономическими входными событиями — фаза Луны, положения светил, транзитные аспекты. **Уровень C:** персональная карта рождения с сопоставлением актуальных транзитов и натальных показателей.

Категории выдачи: общая тема дня; любовь/отношения (Венера, Марс, Луна); работа (Меркурий, Марс, Сатурн); деньги (Венера, Юпитер, Сатурн); внутреннее развитие (Юпитер, Сатурн, повторяющиеся темы). Для солнечных гороскопов интерпретации домов — условные солнечные дома, если выбран этот метод; выдавать их за точные натальные дома нельзя.

**Шаблон дня:** название знака, дата и часовой пояс → общая тема → отношения → работа → деньги → практический совет → краткая метка/настроение → при наличии данные о фазе Луны с явным отличием астрономии от символического совета.

**Плохой гороскоп:** «Сегодня вы непременно встретите любовь и получите деньги». **Хороший:** «День символически связан с вопросами общения; стоит прояснить условия совместных проектов и избегать поспешных выводов». Универсальные утверждения без связи с рассчитанными данными не следует маркировать как «персонально вычисленные».

**Горизонты:** день — Луна/быстрые изменения; неделя — точные аспекты и ближайшие переходы; месяц — лунации, переходы Солнца, динамика быстрых планет; год — долгие циклы. Годовой прогноз нельзя получать простым механическим соединением 365 случайных ежедневных текстов.

**Вариативность:** предложения получают метки `topic`, `theme`, `tone`, `conditions`, `incompatible_with`. После выбора доминантной темы выбираются совместимые фрагменты, устраняются дубли, сохраняется `engine_version`. Для массового гороскопа результат кэшировать один раз на знак/дату/язык/версию, а не пересчитывать для каждого пользователя.

## 8. Ретроградность и лунный календарь

Ретроградное движение планет — **видимое** обратное движение на небосводе. Оно не означает фактическую смену направления орбиты. В западных интерпретациях Меркурий ассоциируют с пересмотром коммуникации, Венеру — ценностей, Марс — стратегии, Юпитер — убеждений, Сатурн — обязательств. Представления о том, что ретроградность физически ломает технику, недоказанны.

Средняя продолжительность синодического месяца около 29,53 суток. Восемь астрономических фаз: новолуние, растущий серп, первая четверть, растущая выпуклая, полнолуние, убывающая выпуклая, последняя четверть, убывающий серп. Символически им приписывают цикл от намерения через развитие и кульминацию к завершению и отдыху.

**Фаза Луны и лунный день — не одно и то же.** В разных лунных календарях «лунный день» может зависеть от местного восхода Луны, а не от количества прошедших суток. Требуется отдельный явно определённый календарный алгоритм. Луна в знаке трактуется в соответствии с общей системой символики знаков; её текущий знак нужно вычислять, а не угадывать по дате.

## 9. Таро RWS: принципы

Для проекта выбираем одну основную колоду — Rider–Waite–Smith (1909): 78 карт = 22 Старших аркана (0–XXI) + 56 Младших (4 масти × 14). В RWS Сила — VIII, Правосудие — XI; в некоторых других колодах номера переставлены.

Старшие арканы выражают крупные символические темы. Младшие — бытовые процессы. Жезлы традиционно соответствуют Огню (воля и действие), Кубки — Воде (эмоции), Мечи — Воздуху (мысль), Пентакли — Земле (ресурсы). Значение карты зависит от позиций, вопроса, соседних карт, выбранной школы и принятого способа чтения перевёрнутых карт.

**Числа Младших арканов:** Туз — начало; 2 — выбор/двойственность; 3 — развитие; 4 — опора/устойчивость; 5 — испытание; 6 — восстановление; 7 — оценка/защита; 8 — работа/процесс; 9 — зрелый результат; 10 — завершение. Паж — ученик/сообщение; Рыцарь — движение; Королева — зрелое внутреннее качество; Король — ответственное внешнее управление. Придворные карты — не обязательное указание на пол человека.

**Перевёрнутые карты:** не всегда означают «строго наоборот». Возможны ослабление, блокировка, уход вовнутрь, избыток или обратное проявление. Например, перевёрнутое Солнце не обязательно указывает на несчастье, а карта Смерть в любом положении не говорит о буквальном физическом исходе.

**Позиция критична:** Император в «ресурсах» — организация и границы; Император в «препятствии» — излишний контроль. Восьмёрка Кубков в работе — желание сменить смысл работы; в отношениях — эмоциональная дистанция; в позиции совета — вопрос о том, что пора отпустить.

## 10. Чтение расклада

**Карта дня:** одна равномерно выбранная карта на локальную дату пользователя; повторные открытия возвращают прежний результат. Показываем изображение (только при наличии прав на визуальный материал), краткое значение, теневую сторону, практический совет и вопрос для размышления.

**Три карты «Ситуация — Препятствие — Совет»:** каждая позиция передаёт отдельную роль. Пример: Влюблённые + Верховная Жрица + Сила = значимый выбор в отношениях, недосказанность как препятствие, терпение и ясный разговор как совет. Финальный текст должен связать значения, а не просто склеить три определения.

**Три карты «Прошлое — Настоящее — Возможное направление»:** третий пункт не следует называть неизбежной судьбой. **Пять карт:** ситуация, поддержка, препятствие, фокус, возможное развитие/совет. **Кельтский крест:** 10 позиций, зафиксировать конкретную версию позиций до реализации; традиционные списки отличаются. **«Да/нет»:** только символическая шкала с неопределённостью, без выдуманных статистических процентов.

**Алгоритм интерпретации:** сначала понять тематику вопроса, затем выбрать карты без возвращения, назначить случайную ориентацию (если включена), получить значение для позиции и темы, выявить согласующиеся и конфликтующие мотивы, сформировать вывод без фатальных предсказаний. Не подбирать карты искусственно под желаемый ответ пользователя.

**Чувствительные запросы:** Таро не определяет смерть, беременность, заболевание, измену, преступление или инвестиционную доходность. Вместо категоричного ответа формировать осторожную символическую интерпретацию и при необходимости отсылать к проверяемым источникам решений.

## 11. Камни, нумерология, руны и другие функции

**Камни:** различать (а) камни по месяцу рождения, (б) по знаку в *конкретном* историческом списке, (в) символический подбор под задачу. Их названия и минералогические свойства можно проверить; утверждения об энергетическом или лечебном действии не доказаны. Привязывать соответствия к названию традиции и не смешивать разные таблицы.

**Нумерология:** распространённая западная система приписывает значения цифрам 1–9, иногда сохраняет 11/22/33 как мастер-числа. Число жизненного пути в одном методе — сумма всех цифр даты рождения с приведением к одной цифре. Пример 14.09.1996: 1+4+0+9+1+9+9+6=39→12→3. Персональный год для 14 сентября и 2026 года: 1+4+9+2+0+2+6=24→6. Отдельно выбрать правило работы с мастер-числами и начало персонального года (1 января либо день рождения). Число имени требует единой таблицы букв/транслитерации.

**Руны:** Старший футарк — 24 исторических письменных знака; современные расклады и значения не следует представлять как достоверно восстановленную древнюю систему гадания. Для первой версии достаточно руны дня с историческим значением, современной интерпретацией и вопросом для самоанализа. Не выдавать пустую 25-ю руну за древнюю.

**Китайский зодиак:** 12 животных и пять элементов, полный цикл 60 лет. Для января/февраля важно выбрать календарный метод границы года: китайский Новый год или Личунь. Упрощённый выбор животного по календарному году без учёта даты рождения даст ошибки на границе.

**Другие будущие функции:** аффирмации, медитации, сонник (только символически), синастрия двух карт, совместимость знаков (как развлекательный архетипический режим), символ и цвет дня. Не подключать их ценой нестабильного основного приложения.

## 12. Техническая концепция

**Платформа:** Telegram webhook → Cloudflare Worker → D1 (пользователи, настройки, история, кэш) + локальные или импортируемые JSON-справочники → движок интерпретации → Telegram Bot API. Рассылки через Scheduled Handler / Cron Triggers. Деплой только после проверки binding `DB`, переменных окружения и истории миграций.

**Вычисление планет:** для общего геоцентрического тропического знака необходима корректная геоцентрическая эклиптическая долгота; не путать её с гелиоцентрической долготой библиотеки. Рассматривать Astronomy Engine (JS/TS, MIT) как старт астрономии. Swiss Ephemeris подходит для профессиональных астрологических расчётов, но потребует соблюдения условий лицензирования и отдельной проверки интеграции. Система домов требует отдельного проверенного модуля.

**Три уровня персонализации:** A — только знак; B — знак + текущие точно вычисленные небесные события; C — полноценные натальные данные с транзитами. При отсутствии рождения по времени не рассчитывать достоверный ASC.

**База D1:** `bot_users_v2`, `tarot_daily_cards`, `tarot_readings`, `tarot_draws`, `horoscope_cache`, `star_transactions`, `dispatch_log`, `processed_updates`. SQL находится в `database/schema.sql`. Взвешенно хранить персональные данные и обеспечить удаление данных по запросу.

**Таро:** криптографический генератор случайных значений и алгоритм Фишера–Йетса без возвращения; дневная карта с уникальным ключом `(telegram_id, local_date)`; запросы на расклад — отдельные идентификаторы; историю можно просматривать; повторная доставка `update_id` не должна приводить к двойной операции.

**Гороскоп:** рассчитывать один раз на дату/знак/версию движка/язык, хранить кэш, публиковать пользователям нужной зоны. Тексты генерировать из тематически согласованных правил, а не случайного несвязанного набора предложений. Не запрашивать астрономическую библиотеку на каждого пользователя, если исходные данные одинаковы.

**Бонусы:** внутренние «звёзды» — не денежные Telegram Stars. Все начисления и списания вести журналом с уникальным основанием; проверки и списания делать атомарно. Бесплатная карта дня и базовый гороскоп доступны без обязательного привлечения друзей.

**Рефералы:** параметр `/start`, запрет самоприглашения, единожды начисляемый бонус, валидация нового аккаунта. Проверка подписки на канал — `getChatMember` с соответствующими правами администратора; модуль внедрять после MVP.

**Рассылка:** хранить предпочтения и локальную зону пользователя. Если выбирать первоначальное окно 09:00–11:00 по Москве, это соответствует 06:00–08:00 UTC; Cloudflare Cron работает по UTC. Планировать небольшие пачки, логировать попытки, предотвращать дубли и повторять только восстанавливаемые ошибки. Проверять DST при международных пользователях.

## 13. Безопасность, качество, ограничения

Webhook защищать `secret_token` и HTTPS. Telegram token и другие ключи держать в Cloudflare Secrets, никогда не сохранять в открытом репозитории или пользовательском сообщении. Не доверять `telegram_id` и параметрам из произвольных callback-данных без проверки контекста. Проверять лимиты длины вопроса, корректность даты, диапазоны широты/долготы, поддерживаемость часовой зоны и повторяемость операций.

**Ключевые тесты:** отсутствие `DB` даёт диагностический ответ без аварийного падения; `SELECT 1` проходит; `/start` идемпотентен; дата на границе знака не вычисляется по грубым интервалам при включённом точном режиме; без времени рождения ASC не показывается; выбор 3 карт уникален; дневная карта не меняется в пределах даты; повтор webhook не тратит звёзды; повтор бонуса не начисляет его; при выключенной подписке рассылка не идёт; часовые пояса и переход на летнее время обрабатываются; удаление данных действительно удаляет всё связанное с пользователем.

**Ограничения Cloudflare:** бесплатные тарифы и квоты меняются, поэтому перед развёртыванием сверять актуальную документацию. В предыдущем обсуждении использовали ориентиры Workers Free 100 тыс. запросов в сутки, CPU 10 мс на HTTP-запрос, память 128 МБ; D1: 5 млн прочитанных и 100 тыс. записанных строк в сутки, общий объём около 5 ГБ. Это исторический снимок документации, а не гарантия текущего тарифа.

### 18.7. Подробный метод чтения и проверка расклада

1. **Вопрос:** уточнить, о какой сфере идёт речь; не угадывать факты о другом человеке.
2. **Случайность:** равномерно выбрать N уникальных карт из выбранной колоды. Если включены перевёрнутые — отдельно выбрать ориентацию каждой.
3. **Позиция:** назначить роль в раскладе и прочитать карту именно в этой роли.
4. **Масти и повторы:** большое количество Кубков — акцент на переживаниях; Мечей — на мышлении и решениях; Жезлов — на действии; Пентаклей — на ресурсе. Преобладание Старших арканов — метафорический акцент на больших темах, не статистическое доказательство важного события.
5. **Связность:** выделить повторяющиеся мотивы и противоречия между картами; показать, как они соотносятся.
6. **Результат:** дать применимый для размышления совет, не утверждать неизбежное будущее.

**Пример трёх карт:** вопрос «Как разобраться в отношениях?». Ситуация — Влюблённые: необходимость выбора и согласования ценностей. Препятствие — Верховная Жрица: нехватка информации и недосказанность. Совет — Сила: терпение, ясный разговор и границы. Синтез: «Лучше обсудить ожидания без давления и проверить предположения, чем спешить с решением». Это символическое чтение, а не знание истинных намерений партнёра.

**Пример карты дня — Сила:** «Сегодня полезна спокойная настойчивость. Вместо резкого ответа можно выбрать терпение и конкретное действие». Вопрос для размышления: «Где я могу проявить уверенность без давления?».

**Расклады:** одна карта; 3 карты (ситуация/препятствие/совет, прошлое/настоящее/возможное направление); 5 карт (ситуация/помощь/препятствие/фокус/совет); Кельтский крест из 10 позиций (фиксировать выбранный вариант); условный да/нет с честной неопределённостью.

/** AstraBot reference utilities. JS ES module for Cloudflare Workers; not a full bot. */
export function randomInt(maxExclusive) {
  if (!Number.isInteger(maxExclusive) || maxExclusive < 1 || maxExclusive > 2 ** 32) {
    throw new RangeError('maxExclusive must be integer in [1, 2^32]');
  }
  const range = 2 ** 32;
  const limit = Math.floor(range / maxExclusive) * maxExclusive;
  const one = new Uint32Array(1);
  let value;
  do {
    crypto.getRandomValues(one);
    value = one[0];
  } while (value >= limit);
  return value % maxExclusive;
}

/** Equal-probability sample of unique cards. Reversal is independently uniform. */
export function drawCards(deck, count, allowReversed = true) {
  if (!Array.isArray(deck) || !Number.isInteger(count) || count < 1 || count > deck.length) {
    throw new RangeError('Invalid deck or count');
  }
  const ids = deck.map((item) => item.id);
  if (new Set(ids).size !== deck.length) throw new Error('Deck contains duplicate IDs');
  const pool = [...deck];
  for (let i = 0; i < count; i++) {
    const j = i + randomInt(pool.length - i);
    [pool[i], pool[j]] = [pool[j], pool[i]];
  }
  return pool.slice(0, count).map((card) => ({
    ...card,
    is_reversed: allowReversed ? randomInt(2) === 1 : false,
  }));
}

export function interpretPosition(card, position, topic = 'general') {
  const meaning = card.is_reversed ? card.reversed : card.upright;
  return {
    card_id: card.id,
    card_name: card.name_ru,
    position,
    topic,
    // Actual contextual synthesis needs editorial rules, not invented facts.
    core_meaning: typeof meaning === 'string' ? meaning : 'See card dictionary',
  };
}
```

/** AstraBot math references. Input must be a CORRECT geocentric tropical ecliptic longitude. */
export const SIGNS_RU = Object.freeze([
  'Овен', 'Телец', 'Близнецы', 'Рак', 'Лев', 'Дева',
  'Весы', 'Скорпион', 'Стрелец', 'Козерог', 'Водолей', 'Рыбы'
]);
export function normalize360(degrees) {
  if (!Number.isFinite(degrees)) throw new TypeError('Finite angle required');
  return ((degrees % 360) + 360) % 360;
}
export function zodiacFromLongitude(longitude) {
  const normalized = normalize360(longitude);
  const index = Math.floor(normalized / 30);
  return { sign: SIGNS_RU[index], index, degreesWithinSign: normalized % 30 };
}
export function angularSeparation(a, b) {
  const difference = Math.abs(normalize360(a) - normalize360(b));
  return Math.min(difference, 360 - difference);
}
export function findAspects(a, b, aspectDefinitions) {
  const delta = angularSeparation(a, b);
  return aspectDefinitions
    .map(item => ({
      name: item.name_ru,
      target_angle: item.exact_angle_degrees,
      orb: Math.abs(delta - item.exact_angle_degrees),
      allowed_orb: item.proposed_orb_degrees
    }))
    .filter(item => item.orb <= item.allowed_orb)
    .sort((x, y) => x.orb - y.orb);
}
```
