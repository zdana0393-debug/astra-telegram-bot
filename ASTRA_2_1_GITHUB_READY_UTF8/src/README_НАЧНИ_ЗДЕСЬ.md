**Для:** Telegram `@LaDa_Iskra_Opel_Astrabot`  
**Существующий Cloudflare Worker:** `opel-astra-bot`  
**Публичный адрес Worker:** `https://opel-astra-bot.zdana0393.workers.dev`  
**Новая база D1:** `astra-live-v2`  
**Привязка базы:** `DB`  
**Стоимость при соблюдении лимитов Free:** 0 ₽/мес. Оплачивать хостинг и API генерации текста не нужно.

Тебе не нужны Python, Node.js, GitHub и командная строка. Работаем через браузер и Блокнот Windows.

## СНАЧАЛА ПРОЧТИ

- **НЕ УДАЛЯЙ** своего Telegram-бота, старый Worker или старую базу `astra-db`: старую базу оставляем как резервную.
- Во время замены программы Telegram-бот временно перестанет отвечать — это нормально. Мы переподключим его на шаге 6.
- **Никому не отправляй** токен BotFather, значения секретов и полную ссылку `/activate?key=...`. Для диагностики хватит страницы `/health` и скриншота настроек с закрытыми значениями.
- Все действия делай в **Production**, а не Preview. Панель «Preview» справа в редакторе игнорируй: проверяем только опубликованную версию в **обычной новой вкладке** браузера.
- После каждого Deploy открой вкладку **Deployments** и посмотри **Active deployment**, затем проверяй публичный адрес. Если при редактировании сверху остался старый номер версии, перезагрузи страницу и открой **Edit code** заново.
- Все SQL-таблицы v2 названы `astra_...`, поэтому мы не перепутаем их с таблицами старого бота.

## Что умеет первая рабочая версия

1. `/start`: регистрация, выбор одного из 12 знаков, приветствие и гороскоп.
2. Бесплатный ежедневный гороскоп: общий прогноз, отношения, дела, совет, число дня.
3. Таро: бесплатная **карта дня**, которая остаётся той же до следующего дня, и случайный расклад на **три карты за 3 ✨**. Колода: 22 старших аркана.
4. «Звёздная пыль»: 2 ✨ при первой регистрации, +1 ✨ ежедневно, +5 ✨ за нового приглашённого, +5 ✨ за подтверждённую подписку на канал (после подключения канала).
5. Собственные реферальные ссылки, проверка подписки через администраторского бота в канале.
6. Автоматическая утренняя рассылка в Telegram и её отключение пользователем.
7. `/privacy` и `/delete`: объяснение хранения данных и удаление записи пользователя.
8. Защита от дублирующихся обновлений Telegram и повторных начислений бонуса за один день.

**Чего пока НЕТ:** платного ChatGPT API, полной колоды из 78 карт, картинок для карт, личных часовых поясов пользователей и оплаты Telegram Stars. Тексты — заранее написанные разнообразные фразы, собранные по знаку и дате; не индивидуальная генерация искусственным интеллектом. Это развлечение, не достоверное предсказание.

# ЭТАП 1. Создай новую базу (старую не удаляй)

1. Открой `https://dash.cloudflare.com/` и войди в прежний аккаунт.
2. Слева **Storage & databases → D1 SQLite Database** (названия могут немного отличаться).
3. Нажми **Create database**.
4. Имя **`astra-live-v2`**, регион можно оставить автоматический.
5. Открой новую базу и вкладку **Console**.
6. Открой файл **`02_SCHEMA.sql`** в Блокноте. Копируй все строки, вставь в Console, нажми **Execute**.
7. Чтобы проверить таблицы, отдельно выполни:

   `SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;`

   Должны быть таблицы **`astra_users`** и **`astra_processed_updates`** (может также быть системная таблица SQLite).

**Контрольная точка 1:** В новой базе `astra-live-v2` видны две таблицы `astra_...`. Пока больше ничего не делай, если не видишь их.

# ЭТАП 2. Ставим маленькую диагностику вместо старого бота

1. Открой **Workers & Pages → opel-astra-bot**.
2. Нажми **Edit code**.
3. Если редактор сообщает `Only the latest version of your Worker can be edited`, перезагрузи страницу и вернись через **Edit code**; не редактируй старый развёрнутый номер.
4. Открой файл **`00_DIAGNOSTIC.js`** в Блокноте и скопируй весь текст (`Ctrl+A`, `Ctrl+C`).
5. В Cloudflare в главном JavaScript-файле (`worker.js`) выдели ВСЁ и замени вставленным кодом (`Ctrl+A`, `Ctrl+V`).
6. Нажми **Deploy**. Если Cloudflare предложит сохранить и развернуть, подтверди.
7. **Не ориентируйся на Preview справа.** В отдельной вкладке открой:

   `https://opel-astra-bot.zdana0393.workers.dev/health`

   Пока может быть `users_table: "MISSING"`, поскольку Worker всё ещё подключён к старой базе. Это нормально.

**Контрольная точка 2:** Публичный `/health` показывает версию `ASTRA-PREFLIGHT-2.0`, а не `Астра запущена 🌙`. Это доказывает, что именно наш новый диагностический код опубликован.

# ЭТАП 3. Переключаем DB со старой базы на новую

1. Вернись на страницу Worker **opel-astra-bot → Settings**.
2. В разделе **Bindings** найди **D1 database — DB — astra-db**.
3. Нажми **карандаш** у этой привязки. Если можно изменить базу, оставь имя переменной **`DB`**, а базу выбери **`astra-live-v2`**, затем сохрани / Deploy.
4. Если редактировать саму базу нельзя, **удали только привязку `DB`** (НЕ саму базу!), подтверди изменение, затем выбери **Add binding → D1 database** и добавь привязку с именем `DB` к `astra-live-v2`. Опубликуй изменения.
5. Убедись в разделе **Bindings**, что осталась одна строка **`D1 database | DB | astra-live-v2`** в **Production**.
6. В **Deployments** убедись, что обновление активно.
7. Снова открой в новой вкладке:

   `https://opel-astra-bot.zdana0393.workers.dev/health`

Ожидаемый ответ:

```json
{
  "version": "ASTRA-PREFLIGHT-2.0",
  "db_binding": "FOUND",
  "db_query": "OK",
  "users_table": "FOUND",
  "ready": true
}
```

**Контрольная точка 3 — САМАЯ ВАЖНАЯ:** Если `ready` не `true`, **СТОП**. Пришли в ChatGPT именно текст `/health`, **не меняй код дальше**. Таким образом мы не повторим старую ошибку `Missing: DB`.

# ЭТАП 5. Добавляем НОВЫЕ секреты в Production

Открой **Workers & Pages → opel-astra-bot → Settings → Variables and Secrets → Production → Add variable**.

| Variable name | Type | Value |
|---|---|---|
| `ASTRA_BOT_TOKEN` | **Secret** | Твой существующий токен от BotFather для `@LaDa_Iskra_Opel_Astrabot` |
| `ASTRA_WEBHOOK_SECRET` | **Secret** | Новая уникальная случайная строка 32–48 букв/цифр |
| `ASTRA_ADMIN_KEY` | **Secret** | Другая случайная строка 32–48 букв/цифр |

Используй два разных случайных ключа; не повторяй старый `SETUP_KEY`. Их можно создать менеджером паролей. **Ни токен, ни ключи в ChatGPT не присылай.**

**Необязательный способ создать секретные строки локально на Windows:** открой PowerShell, вставь три строки ниже и нажми Enter. Повтори два раза, чтобы получить два РАЗНЫХ значения:

```powershell
$b = New-Object byte[] 24
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
[System.BitConverter]::ToString($b).Replace('-', '')
```

На экране появится случайная строка из 48 шестнадцатеричных символов. Скопируй её только в Secret Cloudflare. PowerShell не нужен, если у тебя есть генератор паролей.

Старые переменные `BOT_TOKEN`, `SETUP_KEY`, `WEBHOOK_SECRET` могут остаться в настройках, но **новая программа их не использует**. Это поможет не перепутать версии. Когда всё заработает, можно будет безопасно убрать устаревшие секреты.

После добавления нажми **Deploy**. Теперь `/health` должен показывать:

```json
{
  "version": "ASTRA-2.0.0",
  "db_binding": "FOUND",
  "db_query": "OK",
  "users_table": "FOUND",
  "secrets_ready": true,
  "ready": true
}
```

**Контрольная точка 5:** `ready: true`.

# ЭТАП 6. Подключаем Telegram webhook

1. Открой приватное окно браузера (`Ctrl+Shift+N`, если доступно).
2. В адресной строке собери ссылку **локально**, используя свой `ASTRA_ADMIN_KEY`:

   `https://opel-astra-bot.zdana0393.workers.dev/activate?key=ТВОЙ_КЛЮЧ`

   В конце вместо примера должен стоять твой сохранённый ключ из Secret `ASTRA_ADMIN_KEY`.
3. Нажми Enter. Ожидается:

```text
WEBHOOK_OK
Bot: @LaDa_Iskra_Opel_Astrabot
Worker: ASTRA-2.0.0
D1: OK
Now open Telegram and send /start.
```

4. Закрой приватное окно. Полную ссылку **не пересылай**, поскольку она содержит секретный ключ. При повторной активации Telegram обновляет webhook того же бота; `drop_pending_updates: true` удаляет старые неразобранные Telegram-обновления.
5. Открой `https://t.me/LaDa_Iskra_Opel_Astrabot` и нажми **Start**, либо отправь `/start`.

**Контрольная точка 6:** В Telegram появилось сообщение с предложением выбрать знак зодиака.

Если `Access denied`: неправильный `ASTRA_ADMIN_KEY`. Если `Missing D1 binding or secrets`: вернись к `/health`. Если `BOT TOKEN belongs to another bot`: в Secret токен не от указанного бота. Если `Activation failed`: сообщи ошибку БЕЗ ключей.

# ЭТАП 7. Проверяем меню и данные (до автоматической рассылки)

Проверь последовательно:

1. Выбери знак зодиака → бот ответит и отправит гороскоп.
2. Нажми «✨ Баланс» → 2 ✨.
3. Нажми «🎁 Бонус дня» → 3 ✨; нажми ещё раз → больше не начислит.
4. Нажми «🃏 Таро» → «Карта дня» → появится карта; повторное нажатие выдаст **ту же карту**, пока в Москве не начнётся следующий день.
5. Нажми «🃏 Таро» → «3 карты» → баланс уменьшится на 3 ✨.
6. Нажми «👥 Пригласить друга» → появится личная ссылка `?start=ref_...`. Награду можно проверить с действительно **новым** Telegram-пользователем.
7. Нажми «🔔 Рассылка» — она отключится; нажми ещё раз — включится.
8. В D1 `astra-live-v2 → Console` выполни:

   `SELECT telegram_id, zodiac, balance, notifications_enabled FROM astra_users LIMIT 10;`

   Должна появиться твоя запись с Telegram ID, знаком и текущим балансом. **Не публикуй Telegram ID пользователей** при демонстрации скриншотов.

**Контрольная точка 7:** Все основные кнопки и сохранение данных работают.

# ЭТАП 8. Включаем автоматические гороскопы

Открой **Workers & Pages → opel-astra-bot → Settings → Trigger events / Triggers → Cron Triggers → Add**.

Вставь выражение:

```text
* 6-7 * * *
```

Если в настройках уже есть старый Cron Trigger для этого же Worker, сначала убери его и оставь только новое расписание.

Нажми Save / Deploy, если предложат. Это **раз в минуту с 06:00 до 07:59 UTC**, то есть между **09:00 и 10:59 по Москве**. В каждый запуск программа берёт до **8** ещё не получивших гороскоп пользователей. Повторная отправка тому же пользователю в тот же московский день обычно предотвращается отметкой в базе. Если отправка явно отклонена Telegram, бот попробует позднее (в рамках утреннего окна), а при блокировке — прекратит рассылку этому человеку.

**Ограничение начальной версии:** до ~960 получателей за утреннее окно при регулярном запуске и успешной отправке. Это расчётная ёмкость, а не гарантия доставки: Cron Trigger может запускаться с задержкой, Telegram может отклонять запросы, а большие аудитории потребуют переделать очередь. Изменения Cron Trigger могут применяться до ~15 минут.

Проверять расписание лучше на следующий день утром по Москве: текущие тесты menu/DB не требуют ждать рассылки.

# ЭТАП 9. Подключаем Telegram-канал (не блокирует основной запуск)

Эта возможность **уже есть в коде**, но для реальной проверки нужен публичный канал с username.

1. Создай или выбери публичный Telegram-канал с username `@...`.
2. Назначь `@LaDa_Iskra_Opel_Astrabot` **администратором** канала — иначе проверка чужих подписок через `getChatMember` не гарантирована.
3. Cloudflare Worker → **Settings → Variables and Secrets → Add variable**.
4. Добавь **Text** переменную `CHANNEL_USERNAME`, значение **`@имя_канала`**.
5. Нажми Deploy, проверь кнопку «🌟 Канал» в Telegram.

Бонус +5 ✨ начисляется лишь один раз после подтверждения. При последующей отписке начисление не отзывается. Канал можно подключить позднее, не мешая работе гороскопов и Таро.

# УСТРАНЕНИЕ ОШИБОК

| Симптом | Что делать |
|---|---|
| В браузере старый текст «Астра запущена» | Не опубликован или не активен новый диагностический код. Проверь Deployments → Active deployment, повтори этап 2. |
| `/health` сообщает `db_binding: MISSING` | Привязка `DB` отсутствует в **Production** активной версии. Проверить Bindings; не трогать SQL. |
| `db_binding: FOUND`, `db_query: ERROR` | Привязка есть, но запрос к базе не проходит. Проверить конкретную выбранную базу и Cloudflare Observability. |
| `db_query: OK`, `users_table: MISSING` | `DB` указывает на старую базу или SQL не выполнен в новой. Повтори этапы 1 и 3, ничего не удаляя. |
| `secrets_ready: false` | Не хватает одного из новых секретов из этапа 5, изменения не опубликованы. |
| «Token and remote not found» справа в редакторе | Это **Preview**, а не публичный сайт. Проверь `/health` в новой вкладке. |
| `/activate` → `Access denied` | Сверь значение `ASTRA_ADMIN_KEY` (не показывая его). |
| `/activate` → `WEBHOOK_OK`, а бот молчит | Проверь `/health`, затем логи Worker **Observability → Logs**, наличие записей в `astra_users`, права/токен. |
| `/start` даёт `no such table: astra_users` | SQL выполнен в другой базе или Worker привязан не к `astra-live-v2`. |
| Рассылка не пришла | Проверь Cron Triggers, московское время, кнопку рассылки и логи. |

## Безопасность и конфиденциальность

- Никому не показывай `ASTRA_BOT_TOKEN`, `ASTRA_WEBHOOK_SECRET`, `ASTRA_ADMIN_KEY` или полную активационную ссылку.
- Telegram бот получает ID пользователя и содержание сообщений, а в D1 сохраняются ID, знак, баланс, даты начислений и отправок, ID пригласившего. Телефон, email и дату рождения код не запрашивает.
- При публичном продвижении стоит оформить политику конфиденциальности и контакт владельца в описании бота. Для европейской аудитории особенно важно соблюдать требования к данным и рассылкам.
- Прогнозы и расклады имеют только развлекательный характер.
